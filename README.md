# Weather Prediction Model
Training a basic ML model to predict weather (future max temp) in Portland

# Background
I wanted to make a simple ML model to predict the weather in Portland, ME using the tutorial of [Weather Prediction With Python And Machine Learning [W/Code] by Database](https://www.youtube.com/watch?v=km95-NMT6lU&t=1033s). It had been a while since I have worked with Machine Learning models [Fall 2024 when I took [Intro to Machine Learning](https://openlearninglibrary.mit.edu/courses/course-v1:MITx+6.036+1T2019/about)], so I wanted to have a refresher through a fun project.

# Following the Tutorial
The video walks through the basics of using a local database, cleaning the data, and training a simple Ridge Regression model to predict maximum temperature for future weather. The program uses publicly available data from NOAA, which maintains comprehensive weather records through their partnership with the Global Historical Climatology Network (GHCN). This collaboration has compiled a database that records historical daily temperature, precipitation, and snow measurements across global land areas. In the tutorial, the database for Orange County Airport was used, but I adapted the approach using the Portland Jetport database to analyze and learn more about my local weather patterns.

# Results
The results had higher errors than the video [MAE of 5.3 compared to the 3.4 in the video]. I think this could be due to the variability of Portland’s temperatures compared to Orange County. While Initially, I thought of using more variables besides the core values provided by NOAA, but other values such as wind speed and wind direction had a lot of null values (30-50%), so I did not want to clean up those data points because removing or imputing such a large percentage of missing values could introduce significant bias and reduce the reliability of the model's predictions. However, the significant error gap suggested that there was still substantial room for improvement through model optimization and feature engineering.

# Finetuning the Model
Despite the feature engineering that included seasonal averaging features (`month_avg`, `day_of_year_avg`) and temporal maximums (`month_max`, `month_day_max`), I decided to experiment with tree-based models (Random Forest and Gradient Boosting) to potentially improve upon the Ridge regression baseline. My rationale was that tree models could automatically discover non-linear interactions between features that Ridge regression cannot capture without manual feature engineering. Specifically, I hypothesized that complex relationships between precipitation and temperature patterns, interactions between current conditions (`temp_max`, `temp_min`, `range`) and seasonal norms (`month_avg`, `day_of_year_avg`), and threshold-based weather phenomena might benefit from the recursive partitioning approach of tree models. Tree-based algorithms excel at capturing conditional relationships—for instance, how the effect of precipitation on maximum temperature might vary depending on the current temperature range or how far current conditions deviate from seasonal averages. Additionally, these models can naturally handle extreme weather events and outliers without the smoothing effects inherent in linear models. 

However, my experiments revealed that Random Forest and Gradient Boosting achieved only marginal improvements over Ridge regression, with MAE reductions of approximately 3-8%. This relatively modest improvement suggests that the features had already captured many of the key patterns that tree models would otherwise discover automatically.

# Next Steps
I realized that further model fine-tuning might not be a beneficial next step, so I looked into the days that had a large temperature difference between the actual and predictions using the ridge regression model and found that there were large errors on magnitudes of 22+ degrees off, so I investigated further to analyze 5 days before each high error prediction and found that all worst-case prediction failures occurred immediately following dramatic single-day temperature swings ranging from 18°F to 30°F. The analysis revealed a clear pattern: the model performed reasonably well during the days leading up to these errors, but completely failed to anticipate sudden weather system changes that caused extreme temperature volatility. For instance, temperatures would remain relatively stable around 55°F for several consecutive days, then suddenly jump to 79°F (+24°F change) or plummet from 85°F to 55°F (-30°F change) overnight. Because of this discovery, I plan to focus on incorporating volatility detection features into the model, including rolling temperature standard deviation, day-to-day temperature acceleration metrics, and weather pattern change indicators that can help identify when the typical seasonal patterns are likely to be disrupted by dynamic weather fronts. Rather than trying to predict these extreme swings directly, the goal would be to flag high-volatility periods and apply different prediction strategies or confidence intervals during these unstable weather conditions.
